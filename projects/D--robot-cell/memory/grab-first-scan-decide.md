**"先吸后判"策略(2026-08-27 与用户讨论定型, 待实现)** —— 解叠放误判的治本方案:

旧顺序(现行生产): 拍照 → 用H判"大面朝上"(L−H≥4且W−H≥4) → 不是就丢 → 是才吸 → 扫码 → 上架。
致命伤: 判据把H当"盒自厚"用, 默认盒直接坐桌上; 正叠时H=44.9被垫高, 明明大面朝上却被拒(考题#3实测 W−H=39.2−44.9=−5.7<4 → False)。

新顺序: 拍照 → 只判"这面吸得住吗"(法向水平+面积≥Φ13落脚, **零规格知识**) → 吸起 → 扫码 → 码查SKU三围 → **实测顶面长宽 对 规格三张脸** → 对上大面→上架 / 对上侧面→丢回(将来可加翻面)。

分工一句话: **视觉量出"脸长什么样", 扫码查出"这盒子有哪几张脸", 一比对就知道吸的是哪张**。
- 抓取动作完全SKU无关: 下降深度用实测顶面平面+压紧常数5mm, 不查规格
- 叠放被"从上往下剥"自动消解(吸走上层, 下层变普通单盒), 呼应支线定型的"最高优先抓"
- 侧立盒(Φ13已验证吸得起)不再需要预判丢弃, 扫码后再定去向, 保住选择权
- **H彻底退役(2026-08-27考题#3系列后用户定案)**: 生产不再量桌面/算H/判姿态——吸得住看法向+面积, 下降用面的绝对位置, 去向靠扫码后认脸, 体检用"脸对不上任何已知面"。桌面标定支线只留在vision_steps诊断工具里。#3c实证: H=61.7把骑叠误判成竖立, 认脸(60×22→自厚37→垫高25)才对
- 认脸容差: mask边缘略松致L×W普遍胖2~3mm(三帧实测); 扫码后只在该SKU三张脸里选(60/37/22两两差≥15mm), ±5mm容差足够
- **吸前体检不能靠认脸**(2026-08-27考题#4后用户指正: 多品种下114mm长盒可能真实存在, 吸前未扫码无从比对)。吸前防线全部目录无关: ①落点局部体检(吸盘落点Φ20邻域深度平整连续无台阶——#4事故本质=落点戳两盒接缝, 一查即中) ②法向分家(当选平面内点按局部法向聚类, 两帮拼的=假脸; 现有45°法向过滤拦不住20°分歧) ③真空反馈终审(吸不住立即退回重看, 物理世界不受假脸骗)。认脸的正确位置=扫码后定去向, 不在敢不敢吸
- #4斜靠事故帧背景: mask一锅圈两盒→RANSAC拼出近水平假脸(相对桌面2.6°)→L=114.3跨两盒/H=23.9伪装平躺/face_up=True→落点在接缝=首个"错放"病例(此前全是错杀)

**落地实现(2026-08-31, 真机13.0s全链贯通)**: 认脸链=码→阿里健康API(storage/trace_query.py, 凭证config/trace_query.ini不入git)→**批准文号|包装规格**当SKU钥匙(实证: 同品种两盒不同码查回文号全同; 码前缀方案证伪-三码仅前11位同且与批次纠缠)→自维护尺寸库config/sku_dims.yaml(卷尺实测, 首条S20070026麻腮风60.0x38.5x22.4承v1 placement map)→identify_face三张脸±5mm比对(tools/grasp/sku_face.py, 离线四连测: 大面/侧面/端面/对不上→体检报警全对)。串烧F段打印判决(0.4s, API比预想快), 去向路由归第二版。**API返回无尺寸**(疫苗身份信息: 药名/文号/厂家/批号/效期)——尺寸库必须自养, 新品种流程=报"未登记"→卷尺量→添一行。**v1遗产**: placement_maps(S20070026_at_L6_left.yaml)含完整装箱智慧(7x6x3=126盒/格口+释放偏移+码放顺序), 上架对接时直接继承。

**Why:** 去向判断绕不开"是不是大面", 但不必发生在吸之前——扫码后规格自然到手, 判断时机后移即可绕开H被叠放污染的问题; 改动全在策略层(pick_and_scan流程编排), 视觉层一行不改。
**How to apply:** 实现时动 pick_and_scan_v1 的编排; 用考题库回归(至少#0平躺/#1系列侧立/#3正叠); step7的H及同帧拟合保留作诊断/报警, 不再是生产去向依据。相关: [[vision-exam-bank]] [[yolo-seg-project]]
