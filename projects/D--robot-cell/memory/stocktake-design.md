**结论**: 现有深度相机(法兰旁, 比TCP高76 后397)在格口前一帧就能数出每列盒数, 不加激光. 帧间重复≤1mm.

**算法**: 臂到悬停点→按格口自算下降(相机离上板≥15/目标离板85/杆离板≥15; 悬停高拍时杆挡画面中央一条, 降低后杆落到盒下)→一帧→点云换到货架系(手眼+TCP+立放账本原点)→层板上方高度带→每5mm细条取前脸中位距离→同帧空区域实测背板为基准(抵消相机~+20mm偏差)→盒数=叠厚/节距, 给各盒数假设概率(σ_m 3mm 不累积 + n×σ_p 累积), <90% 标疑似.

**节距 pitch_mm ≠ 卡尺厚**: 货架里每盒实际占厚含缝. 麻腮风 22.4→22.81, 脊灰 25→26.99, 甲肝 23→27.67(缝4.7, 放置压不紧待查). 学法: 用户确认盒数的列(≥4盒)叠厚/盒数 → 尺寸表 pitch_mm(`stocktake.sh <格口> <期望> --learn`); 放置推进量/每列可放数也用它. **盘点从不自动改节距**(审计不能依赖被审计对象); 盘点只读尺寸表, 不读账本盒数; 差异比对在上位机.

**用户关切与答复**: 累积误差消不掉→改比法(学节距把每盒偏差压到0.3; 疑似列可用吸盘顶到位仲裁; 激光测距无用因只减不累积项); 盘点要独立于账本; 流程要少: 流程A 新品种=录尺寸→放≥4盒→--learn 一次; 流程B 盘点=空闲时 POST /tasks type=stocktake. 中央列被杆挡→推算+盘点校正, 不加特殊处理. 用户信息过载, 一次一个结论.

**验收 2026-09-17**: 学后 L7_left 四列 3/10/2/4 全100%; 手动拿走 3/1/2 盒 → 报 -3/-1/-2; R10 两列 1/4 ✓. 接口: type=stocktake → stocktake 事件 result{compare[{ledger_count,measured_count,p,diff,suspect}],columns_found,stray}. 文档 V2.1. 网页账本在浏览器: 期望列表靠库存页"复制盘点期望"+pbpaste.

**待办**: 端到端 `stocktake.sh L7_left <期望> --api` 真机; 甲肝缝; 管理软件接入后期望来自数据库.

**2026-09-19 翻转格口盘点位**: 规则不变(相机离板≈85, 杆尖≥板+15), 但"相机比杆尖高 76"改为按末端朝向从手眼平移现算: 标准 +76.3 / 第2~6层工具翻转 −76.3 → 翻转格口须上升约 118(杆尖升到上层板以上, 在货架前方空中; 10 格口仿真升 130 零碰撞). 标准格口结果不变(R10 降21, L10 降64). 翻转格口默认拒绝, 现场 stocktake.sh <格口> --allow-flip 验证, 通过后账本加 stocktake_flip_ok=true. 识别/计数算法本身不受影响(用实际位姿换算三维点, 与画面朝向无关).
