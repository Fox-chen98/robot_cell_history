为货架每个格口生成"无碰撞、尽量快、可标准化"取放路径的调试流程，2026-06-01 在 L6_Left 上跑通验证。每个格口只换终点关节角，方法不变。脚本见 [[duco-controller-in-loop-bridge]]（blue-space `D:\code\_teach_continue.py`/`_track_run.py`/`_save_path.py`、AutoDL `collision_check_traj.py`/`_combine_check.py`/`_manip_score.py`(评分)/`_select_config.py`(枚举分支+评分+选最优)，均 git 管理）。

**流程（步骤0 选构型 + 8步 出路径）**：
0. **选抓取构型（先于一切，2026-06-02 正式纳入）**：控制器 `movej_pose2(标定TCP, q_near)` 解 IK，`q_near` 不同种子出不同分支（朝前/左摆/右摆×肘上下，最多8组）。**枚举多分支 → 跑 `_select_config.py`（AutoDL：FK出该格TCP→各q_near种子IK→算可操作性分）→ 选 PASS(minσ≥0.12 且 w角≥1.0) 里 w线/±Z 最高的**。**必须排除"朝前/正对"近腕奇异(J5≈0)构型**——它能到达但**伸不进货架**(实测 L6_Right 朝前 movel 伸不进，已改右摆肘上)。详见下方"IK分支/抓取构型选择"。选定后再进第1步。
1. 控制器 movej 点到点（上架中间点→目标格口，**用步骤0选定的构型**）→ blue-space 录制 = **种子轨迹**（关节空间最短，最快最干净，但盲撞）。
2. 发 AutoDL 仿真回放 + 逐点碰撞检测（货架是 URDF 内 `shelf_link`，走自碰撞检测；规划场景 world 为空）。
3. 撞了 → 仿真摆到碰撞点人眼看 → 沿种子**退到碰撞前的安全路点**（人指定索引，如退到 p120/p140）。
4. 人**手动**（示教器切真机模式、极慢速、反复确认）把真机移到一个**有余量绕开障碍的安全位姿**；Claude 读六轴角（`blue_space_state.py`，只读）。模式切换由人在示教器做。
5. 控制器 movej 录两段：前安全点→示教安全点、示教安全点→最终点。
6. 拼接 种子安全段 + 两新段 → 仿真整条逐点碰撞检测。
7. **trackJointMotion 连续跑**串 [中间点, p120, 安全点, 最终点]（**稠密入队~80点**）→ 录真机执行轨迹 → 仿真复验碰撞 + mesh 间隙。
8. 存路径（关键路点 + 入队点 + 实测轨迹）到该格口文件夹 `D:\Destop\robot_code\轨迹探索\<格口>\`（2026-07-22 迁自 C 盘, 文件夹名就是 Destop 无k）。

**关键经验（踩坑/反直觉，务必记住）**：
- **时间被主导关节卡死**：本动作 j5 手腕扫 ~223° 是瓶颈；避障绕行只要和 j5 大扫**时间上重叠**就几乎不额外占时。纯 movej 9.21s，无碰撞版 ~10s 已接近时间地板（j5 必转那么多，省不掉）。
- **"感觉慢"多半是分段停顿**：分段 movej 在每个路点减速停（如 12.17s），改 trackJointMotion 连续跑去掉停顿即回到 ~10s。
- **别只给 trackJointMotion 3 个关键路点**：稀疏点会让控制器样条融合**过冲**（实测 j3 过冲到 -139°，超过示教的 -136°），把上臂 `link_2` 甩进货架 → 引入新碰撞。**必须稠密入队(~80点)**贴合几何路径。
- **中间路由点(如 p120)不是多余**：它保证抬升前手臂先安全到位，去掉会让近端连杆撞货架。
- **几何估算会骗人 → 必须"让控制器算了再仿真验证"**：3 点版几何线性插值估 8.78s 且零碰撞，真机实跑 10.07s 且撞 link_2。trackJointMotion 的融合/过冲只有真机录制出来才知道，所以闭环必须是"控制器原生指令执行 + 仿真验证"。
- **余量要量化、不接受"刚好不撞"**：auto 最小扰动修复余量仅 0.3mm；用 mesh-to-mesh 测吸盘/手臂离货架最小间隙，目标 ~30-50mm；不够就**重新示教更大余量的安全点**（如旋转手腕 j4 换间隙，已实践 v2）。
- **加余量 vs 平滑的权衡（L7_Left 2026-06-02）**：给已无碰撞的路径加安全空间时，示教一个离货架更远的安全点后——**分段 movej（mid→safe→final 两条独立 movej）完整保留余量，但安全点处必有停顿**（movej 点到点是"静止→静止"，两条衔接处减速到零再启动；停顿来自分段、不是规划失败）；**trackJointMotion 连续跑会融合拐角、把安全点抄近 → 削掉部分刚加的余量**。要最大余量选分段(代价一个停顿)，要顺滑选连续(余量打折但仍优于原)。
- **能全局规划绕开的格口不必示教（L7_Left）**：基础路径用纯 MoveIt 多候选(`_multi_plan.py` prefix+goal)+用户逐条播放选形状(候选4 BITstar 最直接)+trackJointMotion 执行录制，零示教即得无碰撞路径；示教只在"还想再加余量"时才上。
- **三种方法定位**：①纯 movej（快但盲撞，仅用于确认无遮挡空域）②auto 局部修复（CHOMP/TrajOpt 式种子引导优化，最小绕行最快 ~9.2s，但需优化器、深凹格/中柱可能失败）③人工示教（可靠、靠人空间判断、可标准化、难例也能行，~10s）。先试便宜的①②，难例退到③。

**IK 分支 / 抓取构型选择（2026-06-02 新增，关键）**：同一格口 TCP 有最多 8 组离散 IK 解（肩×肘×腕各二选一；冗余/奇异处才变连续无穷），用 `movej_pose2` 的 `q_near` 种子选分支（种子在哪个分支就解出哪个；可拿历史 found_positions 的 configA 等当种子"传承"分支）。**构型好坏看货架内取放的可操作性（manipulability），不靠感觉**：
- **判据（脚本 AutoDL `_manip_score.py`，FK 数值雅可比）**：`minσ_full`(整条离奇异距离)≥0.12 **且** `w角`(朝向可操作度)≥1.0 → PASS（能做货架内 movel 插入/横向/升降且保持垂直朝向）；否则 FAIL。还报 `w线`、各方向线性 `+Y(插入)/±X(横向)/±Z(升降)`。
- **腕奇异是元凶**：`J5 近 0/±180°` = 腕部奇异（J4/J6 共线丢自由度）→ `w角` 崩 → movel 保持不住朝向 → **所有方向都受限**（不只插入；横向纯线性看着 OK 但因调不动朝向也不行）。
- **J1 朝向是腕奇异的视觉代理**：垂直抓偏一侧格口时，`J1≈0 正对`→腕被逼向奇异(J5→0)→FAIL；`J1 偏向格口侧`(摆动构型)→腕健康→PASS。**左格 J1 偏左、右格 J1 偏右、正对最差**——这条用户直觉已被数值证实。
- **选构型流程**：枚举多分支(q_near) → 各算分 → 选 PASS 里 `w线`/`±Z` 最高的。
- **验证结论(2026-06-02)**：L6_Left/L8_Left/L8_Right 选用的**摆动构型全 PASS**；所有**朝前构型 FAIL**。**坑：L6_Right 之前存的"朝前"构型 minσ=0.042 全场最差(FAIL)，那条 movel 插入其实保持不住朝向、功能不合格，需改右摆构型重做**（评分抓出来的次品）。

**Why**：仿真是验证平台而非 1:1 孪生（[[sim-as-validation-platform]]，仿真底座比真机基座高 ~530mm、仿真货架≠标定货架），所以运动用真机控制器原生 movej/trackJointMotion 生成、仿真只做碰撞/间隙的"理智检查"，最终以真机录制为准。人工示教补足自动优化在难例上的不可靠。**抓取构型必须可操作性达标，否则到位了也做不了货架内取放。**

**统一方案（总纲，2026-06-02）**：movej 点到点、MoveIt 全局规划，本质都是**启发式种子**。系统化流程 = ①多源生成候选种子（movej 直达 / MoveIt 规划）②各测碰撞，选**「改动最少」**的种子（分数≈碰撞点数+路径长度增量+不平滑度）③在它上面优化（设安全点/局部修复/去 RRT 冗余 shortcut，**只管路径形状**）④**直接用控制器原生 `trackJointMotion` 执行+录制**——控制器自己做连续时间参数化（主导关节连续、两端加减速、**中途不停**）。**软件不需要 TOPP-RA（多余：喂给 trackJointMotion 会被它重新定时，等于白算）**。**"停顿"来自 MoveIt 默认 IPTP 或分段 movej，用 trackJointMotion 就没有**。人工示教退化成"自动都失败时的兜底"。实证：同一 L6_Right，movej 直达广碰(40点)→改 MoveIt 种子直接零碰撞(改动最少)→shortcut(46→3 via)→trackJointMotion 7.54s 连续零碰撞。区分：TOPP-RA=算时间(多余)；shortcut=清形状(种子抖才用)。

**How to apply**：下个格口套用 **步骤0(评分选构型) + 统一方案(多源种子→选改动最少→优化形状→trackJointMotion执行录制)**，复用 [[duco-controller-in-loop-bridge]] 脚本（含 `_select_config.py`/`_global_plan.py`/`_tier1_smooth.py` 的 shortcut/`_track_run_tier1.py` 通用执行器）；终点取该格口标定关节角（`calibrated_poses.yaml`）。中柱类深凹格见 [[shelf-center-unreachable-zone]]（需 ~15° 偏摆）。
