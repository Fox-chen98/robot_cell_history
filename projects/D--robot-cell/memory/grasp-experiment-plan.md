**抓取实验战役开局(2026-08-28, 与用户讨论定案, 未写代码)**:

- **吸盘现状**: 旧SuctionGripper(hardware/gripper/suction.py)是xMate臂的xCoreSDK, 已失效。
  现行 = **DUCO控制器DO7: 0=吸取, 1=吹开**(主动吹气释放——放置时须贴近再吹/短促, 防吹跑50g盒)。
  **无真空传感器**(旧get_state只是读回DO命令电平, 从来不是反馈)。远期升级: 真空压力开关接DUCO DI(几十块)。
- **吸没吸住的裁判 = 视觉复核**(思路已定, 实现缓行): 吸→抬起→重拍→原位置盒子消失=成功。用九步管线现成判定, 零新硬件。
- **下降安全 = 安全走廊(方案二)**: 落料带上空、桌面3~30cm、仅竖直升降movel的立方体范围, 先一次性沙盘验证走廊本身, 之后走廊内竖直升降免判卷; home↔近拍位大范围运动照旧每次判卷链。
- **实验A剧本**: 九步管线出落点(脸中心×TCP×手眼→基座系) → 下降到盒面+5mm(压紧常数, tool_contact.yaml) → DO7=0吸 → 竖直抬起悬停 → 放回 → DO7=1吹开。
- 实验阶梯: A单盒平躺吸放 → B吸起去scan_hover扫码(先吸后判前半) → C侧立窄面直吸闭环 → D叠放取上层 → E抽枕头(斜靠定案策略实测)。

**选盒策略定案+真机验证(2026-08-28晚)**: 规则="所有实例的所有脸→三道门筛(倾角<10°/窄边≥20mm/高度10~90mm)+证书绿区→过门者**离扫码口近者优先**(用户加的:抓远盒会碰倒近盒;扫码口基座系(-0.877,0.358),由scene_params桌心+scan_port偏移旋转算得,桌子重标须重算)→同垛(距离差<6cm)高者优先"。斜靠→斜面被门筛掉自然轮到平盒(=抽枕头);叠放→上层高者当选;全军覆没→停机不吸。离线实证#4b/#4c当选皆平躺脸(老"取最浅脸"规则在这两帧会撞倾角门停机)。真机多盒混合场景一把过(6脸: 3斜淘汰3过门,候选表逐脸打印判决)。阶梯C(侧立窄面直吸)+竖立同日真机通过。**可视化补齐**: faces_vis.jpg(服务端画:实例轮廓一色+脸矩形/中心/L×W×H×倾角)+grasp_vis.jpg(抓取端画:白框当选脸+红十字落点,try包裹不影响抓取)。**两个坑**: ①臂运动刚停深度流短暂断流(数秒自愈)→服务端取帧6s耐心窗口+一次流重启自救(治标;治本=USB线扎带留余量) ②落点画图曾from services.vision_core import→拖进vision.pose_estimation重依赖**import实测3.1s**,把B段从0.8吹到8.8s——教训: 抓取进程禁止import重视觉模块(代码留禁令注释), 服务化的意义就是把重资产隔离在服务进程。
