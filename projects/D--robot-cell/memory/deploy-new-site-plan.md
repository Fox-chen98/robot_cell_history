用户 2026-10-29 定的部署思路, 详见 docs/交接整理/部署到新设备的思路.md。

- 两角色: 调试电脑(现 blue-space, 全套含 ROS/训练) 带去现场; 运行电脑只装「设备控制台」安装包(自动配环境/服务), 加载参数包运行; 以后更新只换参数包。
- 所有硬件(机械臂网线/相机/扫码器/上苗机)都接在一个扩展坞上, 换电脑只换一根线 → 标定可在调试电脑上做, 结果直接给运行电脑用(我曾误以为相机只能接运行电脑, 用户纠正)。
- 参数包分两部分: 通用(模型/速度/路径库, 布局相同时) 与 本机标定(TCP/手眼/桌子货架位姿/格口账本); 推新模型只换通用部分。串口号等跟电脑走的设置不进参数包, 安装时检测/填写。
- 路径库可复用的前提是机械布局标准化。

**Why:** 用户觉得之前讲的产品化(写死路径/打包环境/安装包)太复杂; 这个两角色模型是用户自己提出的直观版本, 与主流(现场调试+配方下载)一致。

**How to apply:** 现在不实施, 先完成工具箱与路径规划环境; 设计新功能时保持"程序/参数包通用/本机标定/本机设置"四类分开, 别把站点相关值写进代码。相关: [[keep-it-simple]] [[industrialization-roadmap]]

**2026-10-30 用户补充(标定方式)**: 场景标定(地面/桌子/货架码牌)只在**初次部署**时做, 那时还没参数, 所以以**手动拖臂拍 + 自动回 home(直连判卷, 红则 MoveIt 规划)**为主; "按现有参数自动去拍的体检"想不出使用场景, 货架第 6 步已去掉自动行(代码留作命令行)。设计工具箱标定步骤时默认走手动拖臂, 别再优先做全自动。
