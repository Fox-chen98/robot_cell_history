2026-11-02 起速度在工具箱「③ 维护工具 → 速度调整」调: 每格口 去/回 飞行(fly.per_slot, 0.5~2.0) + 格内倍率(stand.scale) + 路段倍率(segment_scale goto/scan/table/drop). B-L10 摸到 飞1.8/格内1.2/路段1.3,1.3,1.2,1.2 → 上架 30.1→25.3s(数据在 docs/速度优化日志.md).

**Why:** 用户想"一个位置摸到极限, 做成工具, 剩下的方便优化"; 用户定"先保留"共用倍率.
**How to apply:** A 货架上架出现碰撞检测报警时, 先怀疑格内 1.2/路段倍率(A 未在此速度单独试过), 退回 1.0. 扫码位直飞格口(scan_hover_to_<格口>)已暂停: 接头段吸盘贴侧扫码器, 路径在 data/plans/path_plan/parked/; 用户觉得"越来越复杂", 别主动再推. 相关 [[shelf-b-walkthrough]] [[keep-it-simple]]

**2026-11-06 待办(用户定先记下, 做去/回程提速时再做): 拍照点→回程路径的接头有大转弯**. fly(approach) 现在从拍照点关节直线接到路径起点(门口悬停点)再并队, 不停车但要掉头; 关节空间夹角 B-L10: -246 列 63° / -108 56° / -2.7 121° / +100 107° / +172.8 122° / +200 125°. 提速后这里最容易冲击/碰撞检测停. 单独 movej 会停一下, 用户不要. 方案: 不接起点, 抄近路接到路径第 N 点(第 20 点时夹角 21/5/29/9/37/55°), 每列要判碰(不在验证过的路径里, 离立柱近), 过不了退回更靠前的点; 接头段可配合起步慢后提速. 计算脚本思路: ik(拍照点) + config/paths/B-L10_to_mid.json traj 求夹角.
